# 第14章 FreeBSDの起動処理

電源投入からカーネルの起動、ユーザー空間の初期化、シャットダウンまでの流れと、起動時に指定できる設定を説明します。

<a id="boot-synopsis"></a>
## 概要

コンピュータを起動してOSを読み込む処理を、**ブートストラップ**、または単に**ブート**と呼びます。FreeBSDの起動処理は柔軟で、同じコンピュータにある別のOS、同じOSの別バージョン、別のカーネルなどを選んで起動できます。

本章では、カーネルが読み込まれ、デバイスを検出し、`init(8)` を起動するまでの構成要素と設定を中心に説明します。原文では、この境目を起動メッセージの色が明るい白から灰色へ変わる時点として説明していますが、表示方法によって見え方は異なります。

起動処理の各段階の関係、起動を制御するオプション、デバイスヒントの基本、シングルユーザー・マルチユーザーモードと正常な停止方法を学びます。**対象はx86・amd64です。**

**訳注：** 固定原文の主要部分は旧来のBIOS・MBR・bsdlabel構成を説明しています。現行のUEFI/GPT構成へそのまま当てはめる手順ではありません。とくにブートコードを書き換える例は、自分の起動方式を確認してから扱ってください。

<a id="boot-introduction"></a>
## 起動処理の全体像

OSが動く前に、ディスク上のOSをどう読み込むのでしょうか。この最初の一歩を担うのが、ファームウェアと小さな起動プログラムです。bootstrapという言葉は、ミュンヒハウゼン男爵の物語にある、自分の靴のつまみを引っ張って自分を持ち上げるという話になぞらえたものです。

従来のx86 BIOSでは、ディスクの決まった場所にあるMBR（Master Boot Record）を読み込んで実行し、その小さなプログラムへ残りの起動を任せます。MBRのコード、とくにOS選択などの対話機能を持つものを、**ブートマネージャ**と呼びます。追加コードをディスク先頭のトラックやファイルシステム内に置く場合もあります。FreeBSDのboot0（Boot Easy）やGNU GRUBが例です。GRUBの設定は[GNUの公式文書](https://www.gnu.org/software/grub/grub-documentation.html)を参照してください。

FreeBSDはMBRとGPTの両方の構成で起動できます。GPTはUEFIでよく使われますが、`gptboot(8)` により従来のBIOSからGPTディスクを起動することもできます。**原文の「直接UEFI起動を開発中」という記述は古いものです。** FreeBSDには [loader.efi(8)](https://man.freebsd.org/cgi/man.cgi?manpath=FreeBSD+12.4-RELEASE&query=loader.efi&sektion=8)によるUEFI起動が実装されています。以下のMBRの説明と区別してください。

MBR形式では、一つのOSだけなら起動可能（active）なスライスを探して、その起動コードへ制御を渡します。複数OSを使う場合は、選択メニューを出すブートマネージャを使えます。

従来のFreeBSDの起動処理は、その後を三段階に分けています。最初の段階は次のプログラムを動かすための最小限の処理を行い、第二段階でファイルシステムを扱い、第三段階でOSの読み込みを仕上げます。初期の起動コードには容量制限があるため、段階的につなぐことで柔軟なローダを実現しています。

カーネルが起動すると、デバイスを検出して初期化します。その後ユーザー空間の `init(8)` へ制御を渡し、ファイルシステムの確認・マウント、ネットワークの設定、サービスの起動などが進みます。

<a id="boot-boot0"></a>
### ブートマネージャ（第0段階）

<a id="boot-boot0-example"></a>

MBRのブートマネージャを、起動の**第0段階**と呼ぶこともあります。原文ではFreeBSDのboot0を説明しています。これは従来のMBR構成の話で、すべてのインストールでboot0を使うという意味ではありません。

`/boot/boot0` を基にするコードは、MBR内のスライステーブルと末尾の `0x55AA` 識別子を除いた446バイトに収まる必要があります。複数OSがある場合の表示例です。

```text
F1 Win
F2 FreeBSD

Default: F2
```

FreeBSDの後から別のOSを入れると、既存MBRが上書きされる場合があります。原文はMBRをFreeBSDのものへ戻す例として次を挙げています。

```shell
# fdisk -B -b /boot/boot0 device
```

**これはディスクの起動コードを書き換える操作です。** `device` は実際の起動ディスクを示す置換用の名前です。原文では旧来のIDEの `ad0`、別のIDEコントローラの `ad2`、SCSIの `da0` を例にしています。これらを現在の自分のデバイス名だと決め付けないでください。UEFI/GPTへこのMBR用操作を流用しないようにします。boot0の細かい設定は `boot0cfg(8)` を参照してください。

<a id="boot-boot1"></a>
### 第1段階と第2段階

<a id="boot-boot2-example"></a>

従来のスライス・bsdlabel構成では、boot1とboot2は一組で、ファイルシステム外の、起動スライス先頭の領域に置かれます。容量制約から二つに分かれていますが、`/boot/boot` を基に、インストーラや `bsdlabel` により一緒に配置されます。boot0などのブートマネージャはここへ制御を渡します。

`boot1` は512バイトという制限があり、bsdlabelの情報を読んで `boot2` を見つけるだけの小さなプログラムです。boot2はファイルシステムを理解し、カーネルやloaderを選べます。通常は、さらに高機能で設定ファイルも扱うloaderを実行します。boot2で処理を中断したときの例です。

```text
>> FreeBSD/i386 BOOT
Default: 0:ad(0,a)/boot/loader
boot:
```

原文はboot1・boot2を置き換える例として、次を示しています。

```shell
# bsdlabel -B diskslice
```

`diskslice` は起動対象のディスクとスライスです。原文の `ad0s1` は、旧来の最初のIDEディスクの第1スライスを意味します。

**ディスク全体とスライスを取り違えないでください。** 原文は `ad0` のようにディスク名だけを指定すると、スライスを使わない「dangerously dedicated mode」にしてしまう危険を警告しています。実行前に対象と起動方式を確認してください。

<a id="boot-loader"></a>
### 第3段階：loader

<a id="boot-loader-commands"></a>

loaderは三段階の最後を担い、通常はファイルシステム上の `/boot/loader` にあります。組み込みコマンドと、その背後のインタプリタを通じて、対話操作やスクリプトによる設定を行えます。

初期化時にはコンソールとディスクを調べ、起動元に応じた変数を設定します。原文の構成では `/boot/loader.rc` から既定の `/boot/defaults/loader.conf` と個別設定の `/boot/loader.conf` を読み、選択したカーネルとモジュールをロードします。既定値を変更するときは個別設定を使います。

原文では、既定で10秒の待ち時間を設け、中断されなければカーネルを起動すると説明しています。待ち時間やメニューは使用する版・設定で変わります。中断したプロンプトでは変数の変更、モジュールの読み込み・解除、起動・再起動などができます。詳しくは `loader(8)` を参照してください。

| コマンド | 動作 |
|---|---|
| `autoboot 秒数` | 指定秒数のカウントダウン後、中断されなければカーネルを起動します。原文の既定は10秒です。 |
| `boot [-options] [kernelname]` | 指定オプションで起動します。すでに読み込まれたカーネルがある場合はそれを使うため、別名の指定には先に `unload` が必要です。絶対パスでなければ `/boot/kernel` と `/boot/modules` から探します。 |
| `boot-conf` | `kernel` などの変数に従ってカーネル・モジュールを自動構成します。通常は先に `unload` し、必要な変数を変更して使います。 |
| `help [topic]` | `/boot/loader.help` のヘルプを表示します。`index` でトピック一覧を表示します。 |
| `include filename ...` | ファイルを一行ずつ解釈します。エラーが起きると、そのincludeを中断します。 |
| `load [-t type] filename` | カーネル、モジュール、指定種別のファイルを読み込みます。ファイル名以降の引数は対象へ渡します。絶対パスでなければ `/boot/kernel` と `/boot/modules` を探します。 |
| `ls [-l] [path]` | 指定ディレクトリを表示します。省略時はルート、`-l` ではサイズも表示します。 |
| `lsdev [-v]` | 読み込み元にできるデバイスを一覧表示します。`-v` で詳細を表示します。 |
| `lsmod [-v]` | 読み込み済みモジュールを表示します。`-v` で詳細を表示します。 |
| `more filename` | `LINES` ごとに停止しながらファイルを表示します。 |
| `reboot` | 直ちに再起動します。 |
| `set variable`、`set variable=value` | 環境変数を設定します。 |
| `unload` | 読み込み済みのカーネル・モジュールを解除します。 |

通常のカーネルをシングルユーザーモードで起動する例です。

```text
 boot -s
```

別のカーネルを使うときは、いったん解除してから読み込みます。

```text
 unload
 load /path/to/kernelfile
```

原文は、インストール時のGENERICの例を `/boot/GENERIC/kernel`、前回のカーネルを `/boot/kernel.old/kernel` としています。実際にそのファイルが存在し、使いたいカーネルかを確認してください。

別のカーネルに通常のモジュール構成を適用する例です。この場合、原文はカーネル名だけを指定しています。

```text
unload
set kernel="mykernel"
boot-conf
```

自動カーネル設定スクリプトを読む旧来の例です。利用するloaderと機能の対応を確認してください。

```text
 load -t userconfig_script /boot/kernel.conf
```

<a id="boot-init"></a>
### カーネルからinitへ

<a id="boot-kernel"></a>

loader、またはloaderを経由しないboot2から起動したカーネルは、起動フラグを調べて動作を決めます。主なものは次のとおりです。ほかのフラグは `boot(8)` を参照してください。

| オプション | 動作 |
|---|---|
| `-a` | 初期化中に、ルートファイルシステムとしてマウントするデバイスを尋ねます。 |
| `-C` | CD-ROMをルートとして起動します。 |
| `-s` | シングルユーザーモードで起動します。 |
| `-v` | カーネル起動時の情報を詳しく表示します。 |

カーネルの初期化が終わると、`/sbin/init`、またはloaderの `init_path` で指定したプログラムへ制御を渡します。

起動処理ではファイルシステムの整合性を確認します。UFSの不整合を `fsck` が修復できない場合は、管理者が対処できるようシングルユーザーモードへ移ります。問題がなければマルチユーザーモードへ進みます。

<a id="boot-singleuser"></a>
#### シングルユーザーモード

<a id="boot-insecure-console"></a>

`-s` を指定して起動するか、loaderの `boot_single` を設定すると、このモードを選べます。マルチユーザーモードから `shutdown now` で移行することもできます。開始時の表示例です。

```text
Enter full pathname of shell or RETURN for /bin/sh:
```

Enterを押すと既定のPOSIXシェル `/bin/sh` を起動します。別のシェルなら絶対パスを入力します。

このモードは、ファイルシステムの不整合や起動設定の誤りで正常に起動できない場合の修復に使います。通常のネットワーク設定は行われません。ローカルのシステムと設定へ広い権限でアクセスできるため、rootパスワードを忘れた場合の再設定にも利用できます。

その反面、物理的に操作できる人へシステム全体の制御を許すことになります。物理的な保護が必要です。`/etc/ttys` の `console` を `insecure` にすると、シングルユーザーモードへ入る前にrootパスワードを要求します。

```shell
# name  getty                           type    status          comments
#
# If console is marked "insecure", then init will ask for the root password
# when going to single-user mode.
console none                            unknown off insecure
```

ここでの `insecure` は「コンソールの物理的な安全を信頼しない」という意味です。そのため認証を追加しますが、rootパスワードを忘れた際に、この方法だけで再設定することもできなくなります。

<a id="boot-multiuser"></a>
#### マルチユーザーモード

ファイルシステムに問題がなければ、あるいはシングルユーザーモードでの修復を終えて `exit` すると、通常のマルチユーザーモードへ進みます。

rcの初期化処理は `/etc/defaults/rc.conf` の既定値と `/etc/rc.conf` の個別設定を読み、`/etc/fstab` のファイルシステムをマウントします。その後、ネットワーク、システムのデーモン、追加パッケージの起動スクリプトなどを実行します。

詳細は `rc(8)` と `/etc/rc.d` のスクリプト、[第13章](13-config.md#configtuning-rcd)を参照してください。

<a id="device-hints"></a>
## デバイスヒント

loaderは起動時に `/boot/device.hints` を読みます。ここには、デバイスドライバが構成を決める際の手掛かりとなる**デバイスヒント**を変数として保存します。

[loaderのプロンプト](#boot-loader)からも設定できます。追加・変更は `set`、削除は `unset`、表示は `show` です。ファイルで定めた値を上書きできますが、プロンプトで入力した変更だけでは次回起動に残りません。起動後は `kenv(1)` で環境変数を確認できます。

`/boot/device.hints` では一行に一つの変数を書き、`#` をコメントに使います。

```text
 hint.driver.unit.keyword="value"
```

loaderで直接指定する場合の構文です。

```text
 set hint.driver.unit.keyword=value
```

`driver` はドライバ名、`unit` はデバイス番号、`keyword` は設定する項目です。主なキーワードは次のとおりです。

- `at`：接続先のバス。
- `port`：I/Oの開始アドレス。
- `irq`：割り込み要求番号。
- `drq`：DMAチャネル番号。
- `maddr`：使用する物理メモリアドレス。
- `flags`：デバイス固有のフラグ。
- `disabled`：`1` を指定すると無効化。

ドライバ固有の追加項目や必須項目もあるため、各ドライバのマニュアルを確認してください。`device.hints(5)`、`kenv(1)`、`loader.conf(5)`、`loader(8)` も参照してください。

<a id="boot-shutdown"></a>
## シャットダウンの流れ

`shutdown(8)` による正常な停止では、`init(8)` が `/etc/rc.shutdown` の実行を試み、その後プロセスへ `TERM` を送ります。時間内に終了しないものには `KILL` を送ります。

電源管理に対応するシステムでは、`shutdown -p now` で直ちに停止処理を開始して電源を切ります。再起動は `shutdown -r now` です。実行にはroot、またはoperatorグループの権限が必要です。`halt(8)` と `reboot(8)` もあり、細かい違いはそれぞれのマニュアルと `shutdown(8)` を確認してください。

グループへの所属変更は[ユーザーとアカウントの管理](03-basics.md#users-synopsis)を参照してください。原文が対象とする電源管理には、モジュール、またはカスタムカーネルに組み込んだ `acpi(4)` が必要です。
