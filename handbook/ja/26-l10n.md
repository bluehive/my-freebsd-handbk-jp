# 第26章 ローカライズ：i18n・L10nの利用と設定

FreeBSDで、使いたい言語の表示・入力・文字処理を設定する方法を説明します。固定原文にはISO-8859やKOI8、sysconsなど旧来の環境に向けた例もあります。利用する文字コード・端末・アプリケーションを確認し、すべてを現在のUTF-8環境へ一律に適用しないでください。

<a id="l10n-synopsis"></a>
## 概要

FreeBSDは世界各地の利用者・貢献者によるプロジェクトで、中国語、ドイツ語、日本語、韓国語、フランス語、ロシア語、ベトナム語など、多くの言語の表示・入力・処理を扱えます。

**国際化（internationalization）**をi18n、**地域化・ローカライズ（localization）**をL10nと略します。最初と最後の文字の間に、それぞれ18文字、10文字あることに由来します。こうした仕組み・プロトコル・アプリケーションを組み合わせ、希望する言語を利用します。

本章では、ロケール名、ログインシェル、文字コンソール、Xorg、国際化対応アプリケーションの探し方、言語別の設定資料を説明します。事前に[追加ソフトウェアの導入](04-ports.md)を理解しておくと役立ちます。

<a id="using-localization"></a>
## ローカライズを使う

<a id="locale-lang-country"></a>

ロケール名は、基本的に言語・国または地域・文字エンコーディングを組み合わせます。

```text
LanguageCode_CountryCode.Encoding
```

| 言語・地域の部分 | 意味 |
|---|---|
| `en_US` | 米国の英語 |
| `ru_RU` | ロシアのロシア語 |
| `zh_TW` | 台湾の繁体字中国語 |

実際に使える一覧を調べます。

```shell
% locale -a | more
```

現在の設定は次で確認します。

```shell
% locale
```

ISO8859-1、ISO8859-15、KOI8-R、CP437などの文字集合については `multibyte(3)`、登録名は[IANAの文字集合レジストリ](https://www.iana.org/assignments/character-sets)を参照してください。

日本語・中国語などはASCIIだけでは表せず、多バイト文字などを扱う仕組みが必要です。原文はEUC・Big5を例に挙げています。古いプログラムがそれらを制御文字と誤認する場合があり、多バイト・ワイド文字対応を有効にして構築したり、設定を合わせたりする必要があります。FreeBSDのロケールのエンコーディングはXorgとの互換性も考慮されています。

以下では設定方法を、その後に対応アプリケーションの選び方を説明します。ロケール名とエンコーディングは、例の綴りを推測するより、利用するシステムのlocale -aの結果で確認してください。

<a id="setting-locale"></a>
### ログインシェルのロケール

ユーザーの `~/.login_conf`、または `~/.profile`、`~/.bashrc`、`~/.cshrc` など、シェルの起動ファイルで設定できます。原文は主に次の二変数を挙げています。

- `LANG`：基本のロケール。
- `MM_CHARSET`：これを参照するアプリケーションのMIME文字集合。

アプリケーション固有の設定やXorgの起動環境でも、値が適切に引き継がれるか確認します。原文が推奨するのは、シェルごとの記法に依存しにくい[ログインクラス方式](#login-class)です。[起動ファイル方式](#startup-file)も使えます。

<a id="login-class"></a>
#### ログインクラスを使う

シェルを変えても共通するログイン設定で、ロケールとMIME文字集合を渡せます。各ユーザーが設定する方法と、rootがクラスを用意する方法があります。

個人の `~/.login_conf` で、ドイツ語・Latin-1を設定する最小例です。

```text
me:\
	:charset=ISO-8859-1:\
	:lang=de_DE.ISO8859-1:
```

次は繁体字中国語・Big5の例です。原文は、一部のアプリケーションが中国語・日本語・韓国語のロケール指定を十分尊重しない場合の追加設定も含めています。

```text
#Users who do not wish to use monetary units or time formats
#of Taiwan can manually change each variable
me:\
	:lang=zh_TW.Big5:\
	:setenv=LC_ALL=zh_TW.Big5,LC_COLLATE=zh_TW.Big5,LC_CTYPE=zh_TW.Big5,LC_MESSAGES=zh_TW.Big5,LC_MONETARY=zh_TW.Big5,LC_NUMERIC=zh_TW.Big5,LC_TIME=zh_TW.Big5:\
	:charset=big5:\
	:xmodifiers="@im=gcin": #Set gcin as the XIM Input Server
```

**LC_ALLは各カテゴリのLC_*やLANGより優先します。** [environ(7)](https://github.com/freebsd/freebsd-src/blob/releng/15.0/share/man/man7/environ.7)にある優先順位です。上のようにLC_ALLを固定したまま、時刻や通貨だけのLC_*を書き換えても、期待した個別設定になりません。原文コメントの「各変数を変更できる」という説明は、この優先順位を踏まえて読みます。XIMのgcinも実際に利用する入力方式に合わせてください。

システム側にログインクラスを用意するなら `/etc/login.conf` を編集します。

```text
language_name|Account Type Description:\
	:charset=MIME_charset:\
	:lang=locale_name:\
	:tc=default:
```

ドイツ語クラスを定義する例です。

```text
german|German Users Accounts:\
	:charset=ISO-8859-1:\
	:lang=de_DE.ISO8859-1:\
	:tc=default:
```

`tc=default` はdefaultから設定を引き継ぎます。変数の詳細は `login.conf(5)` を参照してください。原文はrussianクラスがあらかじめ定義される構成も紹介しています。

`/etc/login.conf` を編集したら、capabilityデータベースを更新します。

```shell
# cap_mkdb /etc/login.conf
```

原文は、個人の `~/.login_conf` の変更にも、そのファイルを対象にcap_mkdbを実行するよう注意しています。システム用ファイルと個人用ファイルを取り違えず、変更後は新しいログイン環境で値を確認してください。

<a id="chapter-26-heading-06"></a>
##### ログインクラスを割り当てるツール

`language` は以下で使う**ログインクラス名の置換用表記**です。ロケール名そのものを直接指定するという意味ではなく、前節で定義したgermanなどのクラスに置き換えます。

vipwでアカウントを作る場合は、クラス欄へ指定します。

```text
user:password:1111:11:language:0:0:User Name:/home/user:/bin/sh
```

adduserでは、`/etc/adduser.conf` の `defaultclass=クラス名` で新規アカウントの既定値を決められます。個別には対話時のクラス欄で変更します。

```text
Enter login class: default []:
```

または、起動時に指定します。

```shell
# adduser -class language
```

pwでは `-L` を使います。

```shell
# pw useradd user_name -L language
```

既存ユーザーはrootでchpassを起動し、クラスを編集します。

```shell
# chpass user_name
```

<a id="startup-file"></a>
#### シェルの起動ファイルで設定する

シェルごとにファイル名・構文が異なり、それぞれ保守する必要があるため、原文はこの方式を推奨していません。shの個人用は `~/.profile`、システム共通は `/etc/profile`、新規ユーザー向けのひな型は `/usr/share/skel/dot.profile` です。ひな型の変更は、既存ユーザーのファイルを自動更新するわけではありません。

```text
LANG=de_DE.ISO8859-1; export LANG
MM_CHARSET=ISO-8859-1; export MM_CHARSET
```

csh系では、`~/.login`、`/etc/csh.login`、`/usr/share/skel/dot.login` が対応する例です。

```text
setenv LANG de_DE.ISO8859-1
setenv MM_CHARSET ISO-8859-1
```

Xorgの `~/.xinitrc` も、実行するシェルに合う構文が必要です。shの例です。

```text
LANG=de_DE.ISO8859-1; export LANG
```

cshの例です。

```text
setenv LANG de_DE.ISO8859-1
```

ファイル名だけで構文を決め付けず、実際にどのシェルが読むかを確認します。

<a id="setting-console"></a>
### 文字コンソールの設定

<a id="locale-charset"></a>
<a id="locale-console"></a>

**本節は主として旧来のsysconsコンソールの設定例です。vt、UTF-8、GUI端末などへ、そのまま対応するとは限りません。** 使用中のコンソールドライバと文字コードを確認してください。

フォントは `ls /usr/share/syscons/fonts` で調べます。拡張子 `.fnt` を省いた名前を、`/etc/rc.conf` へ指定する原文の例です。

```text
font8x16=font_name
font8x14=font_name
font8x8=font_name
```

キー配列とスクリーンマップもrc.confへ指定します。

```text
scrnmap=screenmap_name
keymap=keymap_name
keychange="fkey_number sequence"
```

スクリーンマップは `/usr/share/syscons/scrnmaps` にあり、指定時は `.scm` を省きます。原文は、VGAが文字の8列目を9列目へ広げる処理と疑似グラフィック領域の干渉を避けるため、対応するフォントとマップを使う場合を説明しています。

キーマップは `/usr/share/syscons/keymaps` にあり、指定時は `.kbd` を省きます。再起動前の試用には `kbdmap(1)` を使います。`keychange` は、キーマップだけでは定義できないファンクションキーの送信列を、端末形式へ合わせるための指定です。

`/etc/ttys` の仮想端末の種類も合わせます。原文の対応表です。

| 文字集合 | 端末の種類 |
|---|---|
| ISO8859-1・ISO8859-15 | `cons25l1` |
| ISO8859-2 | `cons25l2` |
| ISO8859-7 | `cons25l7` |
| KOI8-R | `cons25r` |
| KOI8-U | `cons25u` |
| CP437（VGAの既定） | `cons25` |
| US-ASCII | `cons25w` |

多バイト・ワイド文字向けとして、原文は次のPortsを挙げています。**旧来のソフトウェアを含む一覧で、現在の提供状態やコンソールとの互換性は保証しません。** 導入した場合はpkg-messageとマニュアルで設定を確認します。

| 言語 | 原文のPort |
|---|---|
| 繁体字中国語・Big5 | `chinese/big5con` |
| 中国語・日本語・韓国語 | `chinese/cce` |
| 中国語・日本語・韓国語 | `chinese/zhcon` |
| 日本語 | `chinese/kon2` |
| 日本語 | `japanese/kon2-14dot` |
| 日本語 | `japanese/kon2-16dot` |

`chinese/kon2` は日本語用として原文に記された表記を保持しています。実際のカテゴリと提供状況を確認してください。

mousedが有効で、sysconsのカーソルが使う文字コード0xd0〜0xd3と表示文字が重なる場合、カーソル用領域を動かす例です。

```text
mousechar_start=3
```

<a id="l10n-compiling"></a>
## 国際化対応アプリケーションを探す

国際化のライブラリや仕組みを使うと、表示文字列・メニューの翻訳を別のデータとして用意できます。[Ports Collection](https://ports.freebsd.org/)にも、多言語や多バイト文字へ対応するアプリケーションがあります。原文は名前にi18nを含むものを目印として挙げていますが、**i18nという名前がなくても対応するものはあり、その名前だけで必要な言語への対応が決まるわけではありません。**

文字集合などをビルド時に選ぶソフトウェアもあります。PortのMakefileやconfigureの設定、元ソースの国際化関連文書を参照し、必要なオプションを確認してください。

<a id="lang-setup"></a>
## 言語ごとのロケール設定

以下はロシア語・KOI8-Rの具体例と、ほかの言語向け資料です。旧来の文字コードとコンソール・Xorg構成を組み合わせた例であることを踏まえ、[共通の設定方法](#using-localization)と合わせて読みます。

<a id="ru-localize"></a>
### ロシア語・KOI8-Rの例

ログインシェルには、各ユーザーの `~/.login_conf` へ次を記載します。

```text
me:My Account:\
	:charset=KOI8-R:\
	:lang=ru_RU.KOI8-R:
```

コンソール用のrc.confの例です。

```text
keymap="ru.utf-8"
scrnmap="utf-82cp866"
font8x16="cp866b-8x16"
font8x14="cp866-8x14"
font8x8="cp866-8x8"
mousechar_start=3
```

この例はロケールのKOI8-R、キーマップ名のUTF-8、画面のCP866を併記しています。名前が同じ文字コードの設定だと思い込まず、変換マップとフォントを含む旧来の構成として確認します。`/etc/ttys` の各ttyvにはcons25rを指定します。

原文は、CP866のハードウェア文字集合を持つプリンタ向けに、KOI8-Rから変換する出力フィルタ `/usr/libexec/lpr/ru/koi2alt` を紹介しています。printcapの例です。

```text
lp|Russian local line printer:\
	:sh:of=/usr/libexec/lpr/ru/koi2alt:\
	:lp=/dev/lpt0:sd=/var/spool/output/lpd:lf=/var/log/lpd-errs:
```

現代の任意のプリンタでこの変換が必要という意味ではありません。詳細は `printcap(5)` と[印刷の章](10-printing.md)を参照します。

MS-DOS形式のファイルシステムで、ロシア語ファイル名のロケールを指定するfstabの例です。

```text
/dev/ad0s2      /dos/c  msdos   rw,-Lru_RU.KOI8-R 0 0
```

`ad0s2` やmsdosという表記は原文の旧来の例です。実際のデバイス名とファイルシステム種別、`mount_msdosfs(8)` の対応オプションを確認して置き換えます。

Xorgでは `x11-fonts/xorg-fonts-cyrillic` を導入し、原文の `/etc/X11/xorg.conf` のFiles節で、ほかのFontPathより前へ次を置きます。

```text
FontPath   "/usr/local/lib/X11/fonts/cyrillic"
```

追加のキリル文字フォントもPortsから利用できます。原文はキーボード設定を別のパス `/etc/xorg.conf` として説明していますが、**実際にXorgが読む設定ファイルの場所を確認し、二つのパスを無条件に使い分けないでください。** 旧来のKeyboard節の例です。

```text
Option "XkbLayout"   "us,ru"
Option "XkbOptions"  "grp:toggle"
```

XkbDisableはコメントにします。grp:toggleは右Alt、grp:ctrl_shift_toggleはCtrl+Shift、grp:caps_toggleはCapsLockという例が挙げられています。原文は、最後の設定が動かない場合があるとも述べ、従来のCapsLock操作はラテン文字側でShift+CapsLockと説明しています。現在のXKB・デスクトップ設定へそのまま一般化しないでください。

Windowsキー付きキーボードで、文字以外のキーの配置が合わない場合の追加例です。

```text
Option "XkbVariant" ",winkeys"
```

国際化していないアプリケーションでは、ロシア語XKBが期待どおり動かない場合があります。原文はXtアプリケーションが起動の早い段階で `XtSetLanguageProc(NULL, NULL, NULL);` を呼ぶ例を挙げています。すべてのGUIツールキットが同じ呼び出しを必要とするわけではありません。

原文の追加資料は [X Window向けKOI8の説明](http://koi8.pp.ru/xwin.html)と[KOI8のサイト](http://koi8.pp.ru/)です。外部資料の更新状況も確認してください。
