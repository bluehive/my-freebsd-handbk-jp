<a id="x11-synopsis"></a>
## この章で行うこと

bsdinstallによるFreeBSDの導入だけでは、グラフィカルなユーザーインターフェースは入りません。この章では、オープンソースのX Window System（通称X11）を提供する `Xorg(1)` の導入と設定を説明します。

先に[PackagesとPorts](04-ports.md)で追加ソフトウェアの導入方法を確認してください。ここではGPUドライバーの選択・導入、Xの各構成要素の関係、X.orgサーバー、フォントの導入を扱います。

<a id="x-graphic-card-drivers"></a>
## GPUドライバーを選ぶ

まずGPUを特定し、対応するportのドライバーを導入して、`sysrc(8)` で以後の起動時に読み込ませます。グラフィックス環境を描画するにはGPUを動かすドライバーが必要です。変化が速く複数OSにまたがる分野なので、ベースシステムとは別に開発・配布されています。

| GPU／表示方式 | ライセンス | 原文のモジュール／ドライバー名 | Portsのパス |
|---|---|---|---|
| Intel | オープンソース | `i915kms` | `graphics/drm-kmod` |
| AMD | オープンソース | `amdgpu` または `radeonkms` | `graphics/drm-kmod` |
| NVIDIA | プロプライエタリー | `nvidia-drm`、`nvidia-modeset`、`nvidia` | `graphics/nvidia-drm-kmod` または `x11/nvidia-driver` |
| System Console Framebuffer | オープンソース | `scfb` | `x11-drivers/xf86-video-scfb` |
| VESA BIOS Extension | オープンソース | `vesa` | `x11-drivers/xf86-video-vesa` |
| VirtualBox | オープンソース | `vboxvideo` | `emulators/virtualbox-ose-additions` |
| VMware | オープンソース | `vmwgfx` | `x11-drivers/xf86-video-vmware` |

ドライバーには複数の世代があります。

- **Direct Rendering:** 複数GPUを共存させ、負荷の高い処理を別GPUへ渡すPRIMEに対応します。[GPU設定](#x-config-gpu)で扱います。
- **Kernel Modesetting（KMS）:** カーネル側で表示モードを設定します。`vt(4)` コンソールでのサスペンド・レジュームにはこれが必要です。
- **User Modesetting:** 古い方式もありますが、`sc(4)` コンソールと古いXorgでの利用に限られます。

GPUの特定には次を使えます。

```shell
% pciconf -lv | grep -B3 display
```

Intel Iris Xeの出力例です。

```text
vgapci1@pci0:0:2:0:     class=0x030000 rev=0x0c hdr=0x00 vendor=0x8086 device=0x46a6 subvendor=0x1028 subdevice=0x0b29
    vendor     = 'Intel Corporation'
    device     = 'Alder Lake-P GT2 [Iris Xe Graphics]'
    class      = display
```

> **注意:** Intel・AMD・NVIDIAの対応ドライバーで扱えない場合、原文はSCFBまたはVESAを案内しています。UEFI起動ならSCFB、BIOS起動ならVESAを選びます。起動方式は次で確認できます。

```shell
% sysctl machdep.bootmethod
```

```text
machdep.bootmethod: UEFI
```

> **訳注:** 表の `scfb`・`vesa` はX.org側のドライバーです。Intel・AMDのKMSカーネルモジュールと同じ読み込み方を一律に適用するものではありません。

<a id="x-configuration-intel"></a>
### Intelのグラフィックス

`graphics/drm-kmod` は、Intel GPU用の各種カーネルモジュールを間接的に提供します。新しい版では、特別な設定なしで他のGPUとPRIMEを構成できる場合があります。

パッケージを導入します。

```shell
# pkg install drm-kmod
```

`/etc/rc.conf` の `kld_list` に追加し、起動時に読み込ませます。

```shell
# sysrc kld_list+=i915kms
```

<a id="x-configuration-amd"></a>
### AMDのグラフィックス

AMDも `graphics/drm-kmod` を使い、GPU世代に応じて `amdgpu` または `radeonkms` を読み込みます。[AMD対応表](https://wiki.freebsd.org/Graphics/AMD-GPU-Matrix)で対象機種とドライバーを確認します。

```shell
# pkg install drm-kmod
```

現在の世代の例は `amdgpu` をrc.confに追加します。

```shell
# sysrc kld_list+=amdgpu
```

HD7000／Tahitiより前の古いGPUでは、代わりに `radeonkms` を使います。

```shell
# sysrc kld_list+=radeonkms
```

<a id="x-configuration-nvidia"></a>
### NVIDIAのグラフィックス


NVIDIAは独立GPU向けにFreeBSD用のプロプライエタリードライバーを提供しています。Portsには複数世代向けの版があり、**そのハードウェアが対応する中で新しいもの**を選びます。

| Portsのパス | 読み込むモジュール | 原文が参照する対応ハードウェア |
|---|---|---|
| `graphics/nvidia-drm-kmod` | `nvidia-drm` または `nvidia-modeset` | [一覧](https://www.nvidia.com/Download/driverResults.aspx/210651/en-us/) |
| `x11/nvidia-driver-580` | `nvidia-drm` または `nvidia-modeset` | [一覧](https://www.nvidia.com/Download/driverResults.aspx/274518/en-us/) |
| `x11/nvidia-driver-470` | `nvidia-modeset` | [一覧](https://www.nvidia.com/Download/driverResults.aspx/194639/en-us/) |
| `x11/nvidia-driver-390` または `x11/nvidia-secondary-driver-390` | `nvidia-modeset` | [一覧](https://www.nvidia.com/Download/driverResults.aspx/191122/en-us/) |
| `x11/nvidia-driver-340` | `nvidia` | [一覧](https://www.nvidia.com/Download/driverResults.aspx/156167/en-us/) |
| `x11/nvidia-driver-304` | `nvidia` | [一覧](https://www.nvidia.com/Download/driverResults.aspx/123712/en-us/) |

新しいDirect Rendering用ドライバーの導入例です。

```shell
# pkg install nvidia-drm-kmod
```

起動時の読み込みをrc.confへ追加します。

```shell
# sysrc kld_list+=nvidia-drm
```

カーネルで表示モードを設定するKMSは、以後の起動に対して `/boot/loader.conf` に次を設定します。

```text
hw.nvidiadrm.modeset="1"
```

PRIMEと [Wayland](https://docs.freebsd.org/en/books/handbook/wayland/#wayland-synopsis)にはKMSが必要です。

Direct Renderingに対応しない以前の版では、原文は次のmodesettingモジュールを案内しています。

```shell
# sysrc kld_list+=nvidia-modeset
```

390より古いドライバーはKMSに対応せず、旧 `sc(4)` コンソールと1.20より前の `x11/xorg-server` を必要とすると説明されています。その場合のrc.confの設定例です。

```shell
# sysrc kld_list+=nvidia
```

<a id="firmware"></a>

**ファームウェア**

GPUによっては別途ファームウェアが必要です。`fwget(8)` はPCIデバイスを調べ、必要なファイルを取得して `/boot/firmware` へ導入できます。

> **訳注:** 表には旧世代の対応例も含まれます。新しいX.orgへ古いドライバーを無条件に組み合わせる手順ではありません。

<a id="x-overview"></a>
## X Window Systemの役割

X Window SystemはUNIX系で長く使われてきたグラフィックス基盤です。新しい技術を扱いながら、長年のアプリケーションとの互換性も維持します。デスクトップの各構成要素を含むアプリケーションは、Xorgサーバーを使って表示します。ネットワークも意識した仕組みで、構成要素をネットワーク越しに連携させることができます。

<a id="x-install"></a>
## X.orgサーバーを導入する

GPUドライバーを導入して有効にしたら、X.orgをメタパッケージまたはPortsから導入します。フルセットのメタパッケージは手軽ですが、個別のビルド設定の自由度は下がります。

```shell
# pkg install xorg
```

これで従来型のウィンドウマネージャー `twm(1)` などを含むX Window System一式が入ります。多くの場合は、さらに好みの[デスクトップ環境](https://docs.freebsd.org/en/books/handbook/desktop/)を導入・設定します。

グラフィックス環境を実行する利用者は `video` グループへ追加します。`username` を実際のユーザー名へ置き換えます。

```shell
# pw groupmod video -m username
```

起動は `x11/xinit` の `startx(1)` を使うか、ディスプレイマネージャーを導入・設定して起動時にグラフィカルログインを出します。

経験者向けの小さい構成は `x11/xorg-minimal` です。多くの文書・ライブラリ・アプリが省かれるため、必要なアプリが要求する追加部品は別途導入します。

<a id="x-config"></a>
## X.orgを設定する

X.orgは一般的なGPU・モニター・入力機器を自動検出します。まず既定のまま試してください。合わなければデスクトップの設定GUIで調整するか、以下の方法で手動設定します。

<a id="x-config-files"></a>
### 設定ファイルの置き場所

従来は `/usr/local/etc/X11/` の設定ファイルでX.org全体を構成しました。特殊な場合には今も使えますが、手動の固定設定は動的な自動検出と衝突することがあります。

自動構成が失敗していないなら、単一の `xorg.conf` を新規作成したり `Xorg -configure` を実行したりしないでください。

X.orgは複数の場所を探しますが、FreeBSDで推奨されるのは `/usr/local/etc/X11/` です。OS本体と追加アプリの設定を分離できます。必要な項目だけを `/usr/local/etc/X11/xorg.conf.d/` の小さなファイルに分ける方が、1つの大きなxorg.confより扱いやすくなります。

<a id="x-config-gpu"></a>
### GPUを指定し、複数GPUを使う


Direct Renderingでは、統合GPU（iGPU）と独立GPU（dGPU）をPRIMEで組み合わせられます。負荷の高い処理をdGPUへ渡し、使わない間は電源を落とす仕組みです。より強いGPUでアプリを起動するには `DRI_PRIME=1` という環境変数を使います。

複数ドライバーが衝突するなど手動指定が必要な場合は、`/usr/local/etc/X11/xorg.conf.d/` に設定を置きます。以下は原文の各例です。

<a id="x-config-video-cards-file-intel"></a>

**Intel: `/usr/local/etc/X11/xorg.conf.d/20-intel.conf`**

```text
Section "Device"
	Identifier "Card0"
	Driver     "intel"
EndSection
```

<a id="x-config-video-cards-file-amd"></a>

**AMD: `/usr/local/etc/X11/xorg.conf.d/20-radeon.conf`**

```text
Section "Device"
	Identifier "Card0"
	Driver     "radeon"
EndSection
```

<a id="x-config-video-cards-file-nvidia"></a>

**NVIDIA: `/usr/local/etc/X11/xorg.conf.d/20-nvidia.conf`**

```text
Section "Device"
	Identifier "Card0"
	Driver     "nvidia"
EndSection
```

NVIDIAの基本設定には `x11/nvidia-xconfig` も利用できます。

<a id="x-config-video-cards-file-sfcb"></a>

**SCFB: `/usr/local/etc/X11/xorg.conf.d/20-scfb.conf`**

```text
Section "Device"
	Identifier "Card0"
	Driver     "scfb"
EndSection
```

<a id="x-config-video-cards-file-vesa"></a>

**VESA: `/usr/local/etc/X11/xorg.conf.d/20-vesa.conf`**

```text
Section "Device"
	Identifier "Card0"
	Driver     "vesa"
EndSection
```

複数GPUを区別するには `BusID` を指定します。候補となるPCI位置を調べます。

```shell
% pciconf -lv | grep -B3 display
```

IntelとNVIDIAがある場合の出力例です。

```text
vgapci0@pci0:0:2:0:     class=0x030000 rev=0x0c hdr=0x00 vendor=0x8086 device=0x46a6 subvendor=0x1028 subdevice=0x0b29
    vendor     = 'Intel Corporation'
    device     = 'Alder Lake-P GT2 [Iris Xe Graphics]'
    class      = display
--
vgapci0@pci0:1:0:0:     class=0x030200 rev=0xa1 hdr=0x00 vendor=0x10de device=0x25b9 subvendor=0x1028 subdevice=0x0b29
    vendor     = 'NVIDIA Corporation'
    device     = 'GA107GLM [RTX A1000 Laptop GPU]'
    class      = display
```

<a id="x-config-video-cards-file-multiple"></a>

原文は `/usr/local/etc/X11/xorg.conf.d/20-drivers.conf` に次のように記述する例を示しています。

```text
Section "Device"
	Identifier "Card0"
	Driver     "intel"
	BusID     "pci0:0:2:0"
EndSection

Section "Device"
	Identifier "Card1"
	Driver     "nvidia"
	BusID     "pci0:1:0:0"
EndSection
```

> **訳注:** 上は原文のままの例です。`pciconf` の `pci0:…` 表示とX.orgのBusID書式を混同しないでください。[X.orgのxorg.confマニュアル](https://www.x.org/archive/X11R7.0/doc/html/xorg.conf.5.html)は `PCI:bus:device:function` という形式を説明しています。実際に設定する際は、利用中のX.orgのmanページと検出位置に合わせて指定します。また、これらのX.org側のドライバー指定は、前節で読み込むKMSカーネルモジュール名とは別です。

<a id="x-config-monitors"></a>
### モニターを設定する

多くのモニターはEDIDを提供し、X.orgはそこから対応する解像度・リフレッシュレートを取得して適切な組み合わせを選びます。別の対応モードを使う場合は、X起動後に `xrandr(1)` で変更するか、X.orgの設定ファイルへ記述します。


<a id="x-config-monitors-file"></a>
#### 設定ファイルで解像度を指定する

固定の設定が必要なら、`/usr/local/etc/X11/xorg.conf.d/10-monitor.conf` に画面設定を置けます。1024×768の原文例です。

```text
Section "Screen"
	Identifier "Screen0"
	Device     "Card0"
	SubSection "Display"
	Modes      "1024x768"
	EndSubSection
EndSection
```

<a id="x-config-input"></a>
### 入力機器を設定する

Xorgはタッチ・ポインティング・キーボード機器を統一的に扱う `x11/libinput` を使い、特別に指定しなければ自動で読み込みます。各設定はデスクトップのGUI、または `x11/xinput`・`x11/setxkbmap` で調整できます。

古く軽量な機器別のxf86-input系ドライバーもありますが、その方法ではX.orgの手動設定が必要です。以下では実行中の変更とファイルによる指定を説明します。

<a id="x-config-input-atmoic"></a>
#### 入力設定を実行中に変更する

libinput対応機器はデスクトップの設定GUI、またはxinput・setxkbmapで動作中に調整できます。引数なしの `xinput(1)` は、現在接続されている機器を表示します。

```text
$ xinput
```

出力例です。


対応する設定はプロパティとして列挙・変更できます。ポインティング機器は多くのプロパティを持ちますが、キーボードでは通常は細かな調整が要りません。配列を変更する場合は `setxkbmap(1)` を確認します。

調整できたら、必要なコマンドを `~/.Xsession` や `~/.xinitrc` などのX初期化スクリプトへ追加します。

> **訳注:** 初期化ファイル名の大文字・小文字と読み込み方は、利用するセッション起動方法に合わせてください。

<a id="x-config-input-file"></a>
#### 設定ファイルで入力機器を指定する


KDE Plasmaなど、これらの項目を変更できるGUIを持つ環境もあります。手動編集に進む前に確認します。

<a id="x-config-input-keyboard-layout"></a>

キーボード配列を手動設定する原文例は、`/usr/local/etc/X11/xorg.conf.d/00-keyboard.conf` です。

```text
Section "InputClass"
        Identifier "Keyboard1"
        MatchIsKeyboard "on"
        Option "XkbLayout" "es, fr"
        Option "XkbModel" "pc104"
        Option "XkbVariant" ",qwerty"
        Option "XkbOptions" "grp:win_space_toggle"
EndSection
```

これはスペイン語・フランス語などの配列と切り替えを示す例です。自分のキーボードに合わせて選びます。

<a id="x-fonts"></a>
## X Window Systemでフォントを使う

追加フォントはPortsの `x11-fonts` カテゴリから入れるか、利用者のフォントディレクトリへ配置します。新しいアプリケーションはキャッシュを更新すれば利用できます。古いアプリケーション向けの設定も後述します。

Xには、ベクター／アウトラインフォントを描画するX FreeTypeインターフェース `Xft(3)` と、古いアプリやフォントとの互換性を保つXLFDの仕組みがあります。原文は画面表示用としてOpenType・TrueType、印刷用としてAdobe PostScript Type 1を紹介しています。いずれもアウトライン方式で、ほかにビットマップフォントもあります。

Portsには高品質なフリーフォントが多数あります。システム全体のものは `/usr/local/share/fonts/`、個人用は `~/.fonts/` または `~/.local/share/fonts/` に置きます。サブディレクトリも含め、キャッシュの再構築後に使えるようになります。

```shell
% fc-cache
```

詳しくは [Fonts and FreeBSD](https://docs.freebsd.org/en/articles/fonts/)を参照してください。

<a id="truetype"></a>
### TrueTypeフォント

X.orgはTrueTypeの描画に対応します。原文は、ほかの描画バックエンドとの整合性からfreetypeを使う方法を説明し、`/usr/local/etc/X11/xorg.conf.d/90-fonts.conf` の `Module` 節へ次を追加する例を示しています。

```text
Load  "freetype"
```

> **訳注:** これは旧来の手動設定の説明です。[X.orgのフォント文書](https://xorg.freedesktop.org/releases/current/doc/xorg-docs/fonts/fonts.html)では、多くのプラットフォームでフォント機能は組み込みとなり、実行時ロードのモジュールを使わないと説明しています。新しい環境へ無条件に追加するのではなく、まず前節のFontconfigによる認識を確認します。

手動でXの従来型フォントシステムへ登録する場合、たとえば `/usr/local/share/fonts/TrueType` を作り、フォントファイルをコピーします。原文は、Macのフォントをそのまま持ってくるのではなく、X.orgが扱えるUNIX／MS-DOS／Windows形式のファイルが必要と説明しています。

索引作成ツールを導入します。

```shell
# pkg install mkfontscale
```

原文の索引作成例です。

```shell
# cd /usr/local/share/fonts/TrueType
# mkfontscale
```

> **訳注:** 原文は上の操作を `fonts.dir` の作成と説明していますが、[X.orgの説明](https://xorg.freedesktop.org/releases/current/doc/xorg-docs/fonts/fonts.html)では `mkfontscale` で `fonts.scale` を、続く `mkfontdir` で `fonts.dir` を作成します。従来型の索引が必要な場合は、利用する版のmanページに従い両者を区別します。

フォントパスへ追加します。

```shell
% xset fp+ /usr/local/share/fonts/TrueType
% xset fp rehash
```

または設定ファイルへ `FontPath` を追加します。[Type 1](#type1)も参照してください。原文は、GIMPやLibreOfficeなどでフォントが認識され、小さな文字や大きな文字の表示が改善すると説明しています。

<a id="type1"></a>
### Type 1フォント

`x11-fonts/urwfonts` はTimes Roman、Helvetica、Palatinoなどの高品質なType 1互換フォントを含みます。`x11-fonts/freefonts` はさらに多くのフォントを含みますが、GIMPなどのグラフィックス用途向けが多く、画面の本文用として完全でないものもあります。

URWの導入例です。Freefontsなども同様に導入します。

```shell
# pkg install urwfonts
```

手動構成のXサーバーへ認識させる原文例は、`/usr/local/etc/X11/xorg.conf.d/90-fonts.conf` に次を置きます。

```text
Section "Files"
  FontPath "/usr/local/share/fonts/urwfonts/"
EndSection
```

Xセッション内でパスを追加する方法もあります。

```shell
% xset fp+ /usr/local/share/fonts/urwfonts
% xset fp rehash
```

この変更はセッション終了で失われます。残すならstartxでは `~/.xinitrc`、XDMなどのログインマネージャーでは `~/.xsession` など、実際の開始処理に追加します。第3の方法として、[Fontconfigのlocal.conf](#antialias)で設定する方法もあります。

<a id="antialias"></a>
### アンチエイリアスとFontconfig

`/usr/local/share/fonts/` や `~/.fonts/` にあるフォントは、Xft対応アプリからアンチエイリアス付きで利用できます。KDE、GNOME、Firefoxなど多くのアプリが対応します。

細かな制御は `/usr/local/etc/fonts/local.conf` を作成・編集します。以下は一部の例で、詳細は `fonts-conf(5)` を参照してください。XMLなので、大文字・小文字と閉じタグに注意します。冒頭は次の形です。

```text
<?xml version="1.0"?>
      <!DOCTYPE fontconfig SYSTEM "fonts.dtd">
      <fontconfig>
```

既定のツリー以外のディレクトリを追加するには、fontconfig要素の内側へ次のように記述します。

```text
<dir>/path/to/my/fonts</dir>
```

新しいフォント、特に新しいディレクトリを追加したらキャッシュを作り直します。

```shell
# fc-cache -f
```

アンチエイリアスは輪郭を少しぼかして、小さい文字や大きな文字の段差を滑らかにします。一方、通常サイズの文字では見え方が気になる場合もあります。原文では14ポイント未満を対象から外す例を示しています。

```text
	<match target="font">
	    <test name="size" compare="less">
		<double>14</double>
	    </test>
	    <edit name="antialias" mode="assign">
		<bool>false</bool>
	    </edit>
	</match>
	<match target="font">
	    <test name="pixelsize" compare="less" qual="any">
		<double>14</double>
	    </test>
	    <edit mode="assign" name="antialias">
		<bool>false</bool>
	    </edit>
	</match>
```

等幅フォントの文字間隔がおかしくなる場合、特にKDEなどで、幅を100に固定する方法があります。まず `fixed` と `console` を `mono` の別名にします。

```text
	<match target="pattern" name="family">
	   <test qual="any" name="family">
	       <string>fixed</string>
	   </test>
	   <edit name="family" mode="assign">
	       <string>mono</string>
	   </edit>
	</match>
	<match target="pattern" name="family">
	    <test qual="any" name="family">
		<string>console</string>
	    </test>
	    <edit name="family" mode="assign">
		<string>mono</string>
	    </edit>
	</match>
```

その後monoの間隔を指定します。

```text
	<match target="pattern" name="family">
	     <test qual="any" name="family">
		 <string>mono</string>
	     </test>
	     <edit name="spacing" mode="assign">
		 <int>100</int>
	     </edit>
	 </match>
```

Helveticaなどが縦に半分切れたように見えたり、最悪の場合アプリが落ちたりする問題への対処として、原文はsans-serifへの置き換えを紹介しています。

```text
	<match target="pattern" name="family">
	     <test qual="any" name="family">
		 <string>Helvetica</string>
	     </test>
	     <edit name="family" mode="assign">
		 <string>sans-serif</string>
	     </edit>
	 </match>
```

ファイル全体の末尾は必ず `</fontconfig>` で閉じます。閉じないと変更が無視されます。個人の設定は、同じXML形式で `~/.config/fontconfig/fonts.conf` に置けます。

液晶ではサブピクセル描画を利用する選択肢もあります。赤・緑・青の構成要素を分けて扱い、水平方向の見かけの解像度を上げるものです。閉じタグより前へ、原文の次の設定例を追加します。

```text
	 <match target="font">
	     <test qual="all" name="rgba">
		 <const>unknown</const>
	     </test>
	     <edit name="rgba" mode="assign">
		 <const>rgb</const>
	     </edit>
	 </match>
```

ディスプレイの構成によっては `rgb` ではなく `bgr`、`vrgb`、`vbgr` が適するため、実際の見え方を確認します。
