## 概要

UNIX® では、最初期の UNIX® マシンがユーザーの入出力にシリアル回線を利用していたことから、常にシリアル通信をサポートしてきました。一般的な端末が毎秒 10 文字のシリアルプリンタとキーボードで構成されていた時代から、状況は大きく変わりました。本章では、FreeBSD でシリアル通信を利用するいくつかの方法を説明します。

本章を読むと、次の内容を学べます。

* FreeBSD システムに端末を接続する方法
* モデムを使ってリモートホストへダイヤルアウトする方法
* モデム経由でリモートユーザーが FreeBSD システムへログインできるようにする方法
* シリアルコンソールから FreeBSD システムを起動する方法

本章を読む前に、次の準備を整えておいてください。

* [カスタムカーネルを設定してインストールする方法](09-kernelconfig.md#kernelconfig)を理解しておくこと
* [FreeBSD のパーミッションとプロセス](03-basics.md#basics)を理解しておくこと
* FreeBSD で使用するシリアルハードウェアの技術マニュアルを手元に用意しておくこと

## シリアル通信の用語とハードウェア

シリアル通信では、次の用語がよく使われます。

**bps**
: Bits per Second（ビット毎秒）の略で、データが転送される速度を表します。

**DTE**
: Data Terminal Equipment（データ端末装置）の略で、シリアル通信における 2 つの端点のうち一方を指します。たとえばコンピュータがこれに該当します。

**DCE**
: Data Communications Equipment（データ回線終端装置）の略で、シリアル通信におけるもう一方の端点を指します。通常はモデムやシリアル端末です。

**RS-232**
: ハードウェアのシリアル通信を定義した元の規格です。その後、TIA-232 へと改称されました。

この節では通信のデータ転送速度を表す際に *ボー（baud）* という用語は使いません。ボーは単位時間あたりの電気的な状態遷移の回数を指すものであり、データ転送速度には bps を使うのが正確です。

FreeBSD システムにシリアル端末を接続するには、コンピュータ側のシリアルポートと、シリアルデバイスを接続するための適切なケーブルが必要です。シリアルハードウェアやケーブル配線にすでに詳しい場合は、この節を読み飛ばしても構いません。

<a id="term-cables-null"></a>
### シリアルケーブルとポート

シリアルケーブルにはいくつかの種類がありますが、最も一般的なのはヌルモデムケーブルと標準 RS-232 ケーブルの 2 種類です。必要なケーブルの種類については、ハードウェアの説明書を確認してください。

これら 2 種類のケーブルは、コネクタへの配線のつなぎ方が異なります。各導線は 1 つの信号に対応しており、定義されている信号は [RS-232C 信号名](#serialcomms-signal-names) にまとめています。標準シリアルケーブルは、すべての RS-232C 信号をストレートに通します。たとえば、ケーブルの一端の「Transmitted Data（送信データ）」ピンは、もう一端の「Transmitted Data」ピンにつながります。この種類のケーブルはモデムを FreeBSD システムに接続するときに使われ、一部の端末でも使用されます。

一方、ヌルモデムケーブルは、一端のコネクタの「Transmitted Data」ピンともう一端の「Received Data（受信データ）」ピンを交差させて接続します。コネクタは DB-25 または DB-9 のいずれかです。

ヌルモデムケーブルは、[DB-25 対 DB-25 ヌルモデムケーブル](#nullmodem-db25)、[DB-9 対 DB-9 ヌルモデムケーブル](#nullmodem-db9)、および [DB-9 対 DB-25 ヌルモデムケーブル](#nullmodem-db9-25) にまとめたピン結線を使って自作することもできます。規格上はピン 1 同士をストレートにつなぐ「Protective Ground（保護接地）」線が規定されていますが、実際には省略されることがよくあります。端末によってはピン 2・3・7 のみで動作するものもあれば、別の結線を必要とするものもあります。判断に迷う場合は、ハードウェアの説明書を参照してください。

シリアルポートは、FreeBSD ホストコンピュータと端末との間でデータをやり取りするためのデバイスです。シリアルポートにはいくつかの種類があるため、ケーブルを購入したり自作したりする前に、端末側と FreeBSD システム側の双方のポート形状に適合することを確認してください。

ほとんどの端末には DB-25 ポートが搭載されています。パーソナルコンピュータでは DB-25 または DB-9 ポートが使われます。マルチポートシリアルカードでは RJ-12 や RJ-45 ポートを備えている場合があります。ポートの種類については、ハードウェアに付属の説明書で仕様を確認するか、目視で確認してください。

FreeBSD では、各シリアルポートは `/dev` 配下のエントリを通じてアクセスします。エントリには次の 2 種類があります。

* 着信（call-in）ポートは `/dev/ttyuN` という名前になります（*N* は 0 から始まるポート番号）。端末が 1 番目のシリアルポート（`COM1`）に接続されている場合は `/dev/ttyu0` を、2 番目のシリアルポート（`COM2`）に接続されている場合は `/dev/ttyu1` を指定します（以降同様）。通常、着信ポートは端末に使用されます。着信ポートが正常に動作するには、シリアル回線で「Data Carrier Detect（DCD）」信号がアサートされている必要があります。
* 発信（call-out）ポートは、FreeBSD 8.X 以降では `/dev/cuauN`、FreeBSD 7.X 以前では `/dev/cuadN` という名前になります。発信ポートは通常は端末には使わず、モデムに使用します。ただし、シリアルケーブルや端末が「Data Carrier Detect」信号に対応していない場合には、発信ポートを使用することもできます。

FreeBSD には、初期化デバイス（`/dev/ttyuN.init` および `/dev/cuauN.init`、あるいは `/dev/cuadN.init`）とロックデバイス（`/dev/ttyuN.lock` および `/dev/cuauN.lock`、あるいは `/dev/cuadN.lock`）も用意されています。初期化デバイスは、ポートが開かれるたびに通信ポートのパラメータを初期化するために使用します（たとえば `RTS/CTS` 信号によるフロー制御を行うモデム向けに `crtscts` を設定するなど）。ロックデバイスは、ユーザーやプログラムが特定のパラメータを変更できないよう、ポートのフラグを固定するために使用します。端末設定、ロックデバイスと初期化デバイス、および端末オプションの設定については、それぞれ `termios(4)`、`uart(4)`、`stty(1)` の man ページを参照してください。

<a id="serial-hw-config"></a>
### シリアルポートの設定

デフォルトでは、FreeBSD は一般に `COM1`、`COM2`、`COM3`、`COM4` と呼ばれる 4 つのシリアルポートをサポートしています。また、BocaBoard 1008 や 2016 といったダム型のマルチポートシリアルインターフェースカードや、Digiboard 製のような高機能なマルチポートカードもサポートしています。ただし、デフォルトカーネルが検出するのは標準の `COM` ポートのみです。

システムがシリアルポートを認識しているか確認するには、`uart` で始まるシステム起動メッセージを調べます。

```shell
# grep uart /var/run/dmesg.boot
```

必要なシリアルポートがすべて認識されていない場合は、`/boot/device.hints` にエントリを追加できます。このファイルには、`COM1` 用の `hint.uart.0.*` エントリと `COM2` 用の `hint.uart.1.*` エントリがすでに含まれています。`COM3` のポートエントリを追加する場合はアドレスに `0x3E8`、`COM4` の場合は `0x2E8` を使用します。一般的な IRQ 番号は `COM3` が `5`、`COM4` が `9` です。

ポートで使われているデフォルトの端末 I/O 設定を確認するには、そのデバイス名を指定します。次の例では、`COM2` の着信ポートの設定を確認しています。

```shell
# stty -a -f /dev/ttyu1
```

シリアルデバイスのシステム全体の初期化は `/etc/rc.d/serial` によって制御されており、このファイルがシリアルデバイスのデフォルト設定に影響します。デバイスの設定を変更するには `stty` を使用します。デフォルトでは、変更した設定はそのデバイスが閉じられるまで有効で、次に開き直すとデフォルト設定に戻ります。デフォルト設定を恒久的に変更するには、初期化デバイスを開いて設定を調整します。たとえば、`ttyu5` で `CLOCAL` モード、8 ビット通信、および `XON/XOFF` フロー制御を有効にするには、次のように入力します。

```shell
# stty -f /dev/ttyu5.init clocal cs8 ixon ixoff
```

アプリケーションによって特定の設定が変更されないようにするには、ロックデバイスに対して設定を行います。たとえば、`ttyu5` の通信速度を 57600 bps に固定するには、次のように入力します。

```shell
# stty -f /dev/ttyu5.lock 57600
```

これにより、今後 `ttyu5` を開いてポートの速度を変更しようとするアプリケーションがあっても、57600 bps に固定されたままになります。

## 端末

端末（ターミナル）は、コンピュータ本体のコンソール前におらず、ネットワーク接続もない状況で FreeBSD システムへアクセスするための、手軽で低コストな手段を提供します。この節では、FreeBSD で端末を使用する方法を説明します。

初期の UNIX® システムにはコンソールがなく、ユーザーはコンピュータのシリアルポートに接続された端末からログインし、プログラムを実行していました。

シリアルポート上でログインセッションを確立する機能は、FreeBSD をはじめ今日のほぼすべての UNIX® 系オペレーティングシステムに今も残っています。未使用のシリアルポートに端末を接続すれば、ユーザーはログインして、通常コンソールや `xterm` ウィンドウで実行できるテキストプログラムをすべて実行できます。

FreeBSD システムには多数の端末を接続できます。古い予備のコンピュータを端末として、より高性能な FreeBSD コンピュータへケーブル接続することも可能です。これにより、通常ならシングルユーザー機にとどまるコンピュータを、強力なマルチユーザーシステムとして活用できます。

FreeBSD は次の 3 種類の端末をサポートしています。

**ダム端末（Dumb terminals）**
: ダム端末は、シリアル回線経由でコンピュータに接続する専用ハードウェアです。テキストの表示・送信・受信に足るだけの処理能力しか持たないため「ダム（dumb）」と呼ばれます。この機器自体ではプログラムを実行できず、必要なプログラムを実行するコンピュータへ接続して使います。

  ダム端末には多くのメーカーによる何百種類もの製品があり、ほぼどの機種でも FreeBSD で動作します。上位機種の中にはグラフィックスを表示できるものもありますが、そうした高度な機能を利用できるのは一部のソフトウェアパッケージに限られます。

  ダム端末は、グラフィカルなアプリケーションへのアクセスを必要としない作業環境で広く利用されています。

**端末として動作させるコンピュータ**
: ダム端末に求められるのはテキストの表示・送信・受信能力だけなので、余っているコンピュータであればどれでもダム端末として利用できます。必要なのは適切なケーブルと、そのコンピュータ上で動作する *端末エミュレーション* ソフトウェアだけです。

  この構成は実用面でも便利です。たとえば、あるユーザーが FreeBSD システムのコンソールで作業している最中に、別のユーザーが端末として接続した非力なパーソナルコンピュータから同時にテキストベースの作業を行うことができます。

  FreeBSD のベースシステムには、シリアル接続経由で作業するためのユーティリティが少なくとも 2 つ含まれています。`cu(1)` と `tip(1)` です。

  たとえば、FreeBSD が動作するクライアントシステムから別のシステムのシリアル接続へつなぐには、次のようにします。

```shell
# cu -l /dev/cuauN
```

  ポート番号は 0 から始まります。つまり、`COM1` は `/dev/cuau0` です。

  このほかにも、`comms/minicom` などの追加プログラムが Ports Collection から利用できます。

**X 端末**
: X 端末は最も高機能な種類の端末です。シリアルポートではなく、通常は Ethernet のようなネットワークに接続します。また、テキスト専用アプリケーションに限定されず、あらゆる Xorg アプリケーションを表示できます。

  本章では X 端末のセットアップ、設定、および利用方法は扱いません。

<a id="term-config"></a>
### 端末の設定

この節では、シリアル端末上でログインセッションを有効にするための FreeBSD システムの設定手順を説明します。端末が接続されているシリアルポートをシステムがすでに認識しており、適切なケーブルで端末が接続されていることを前提とします。

FreeBSD では、`init` が `/etc/ttys` を読み込み、利用可能な端末に対して `getty` プロセスを起動します。`getty` プロセスはログイン名を読み取り、`login` プログラムを起動する役割を担います。FreeBSD システム上でログインを許可するポートは `/etc/ttys` に列挙されています。たとえば、1 番目の仮想コンソールである `ttyv0` はこのファイルにエントリがあり、コンソールからのログインを許可しています。このファイルには他の仮想コンソール、シリアルポート、疑似端末（pseudo-tty）のエントリも含まれます。直結（ハードワイヤード）端末の場合、シリアルポートの `/dev` エントリから `/dev` の部分を除いて記述します。たとえば `/dev/ttyv0` は `ttyv0` と記述します。

デフォルトの `/etc/ttys` では、最初の 4 つのシリアルポート（`ttyu0` から `ttyu3`）のサポートが次のように設定されています。

```
ttyu0   "/usr/libexec/getty std.115200"   dialup  off secure
ttyu1   "/usr/libexec/getty std.115200"   dialup  off secure
ttyu2   "/usr/libexec/getty std.115200"   dialup  off secure
ttyu3   "/usr/libexec/getty std.115200"   dialup  off secure
```

これらのポートのいずれかに端末を接続する場合は、デフォルトのエントリを編集して必要な通信速度と端末タイプを設定し、デバイスを `on` に切り替え、必要に応じてポートの `secure` 設定を変更します。これら以外のポートに端末を接続している場合は、そのポート用のエントリを追加します。

[端末エントリの設定](#ex-etc-ttys) では、`/etc/ttys` に 2 台の端末を設定しています。1 つ目のエントリは `COM2` に接続された Wyse-50 の設定です。2 つ目のエントリは、VT-100 端末をエミュレートする Procomm 端末ソフトウェアを実行している古いコンピュータの設定で、マルチポートシリアルカードの 6 番目のシリアルポートに接続されています。

<a id="ex-etc-ttys"></a>
**例: 端末エントリの設定**

```
ttyu1  "/usr/libexec/getty std.38400"  wy50   on insecure
ttyu5   "/usr/libexec/getty std.19200"  vt100  on insecure
```

第 1 フィールドにはシリアル端末のデバイス名を指定します。

第 2 フィールドは、`getty` に対して回線の初期化とオープン、回線速度の設定、ユーザー名の入力プロンプト表示、そして `login` プログラムの実行を指示するものです。省略可能な *getty タイプ* で、bps 速度やパリティといった端末回線の特性を設定します。利用可能な getty タイプは `/etc/gettytab` に一覧されています。ほとんどすべての場合、直結端末では `std` で始まる getty タイプがそのまま動作します（これらのエントリはパリティを無視します）。110 から 115200 までの各 bps 速度に対応する `std` エントリが用意されています。詳細は `gettytab(5)` の man ページを参照してください。getty タイプを設定する際は、端末側で使っている通信設定と一致させてください。この例では、Wyse-50 はパリティなし・38400 bps で接続し、古いコンピュータはパリティなし・19200 bps で接続します。

第 3 フィールドは端末の種類です。ダイヤルアップポートでは、ユーザーが事実上あらゆる種類の端末やソフトウェアで接続してくるため、通常は `unknown` または `dialup` を使用します。一方、直結端末では端末の種類が変わらないため、`/etc/termcap` にある実際の端末タイプを指定できます。この例では、Wyse-50 には実機の端末タイプを指定し、Procomm を実行しているコンピュータにはエミュレート対象の VT-100 を指定しています。

第 4 フィールドはそのポートを有効にするかどうかを指定します。このポートでのログインを有効にするには、`on` を設定する必要があります。

最後のフィールドは、そのポートが安全（secure）かどうかを指定します。ポートを `secure` に設定すると、そのポートから `root` が直接ログインできるほど信頼されていることを意味します。`insecure` なポートでは `root` の直接ログインは許可されません。`insecure` なポートでは、[スーパーユーザーアカウント](03-basics.md#users-superuser)で説明されているように、ユーザーはいったん非特権アカウントでログインしたあと、`su` などの仕組みを使ってスーパーユーザー権限を取得する必要があります。セキュリティ上の理由から、この設定は `insecure` に変更することを推奨します。

`/etc/ttys` を変更したあとは、`init` プロセスへ SIGHUP（ハングアップ）シグナルを送り、設定ファイルを強制的に再読み込みさせます。

```shell
# kill -HUP 1
```

`init` は常にシステムで最初に起動されるプロセスであるため、そのプロセス ID は必ず `1` になります。

すべての設定が正しく行われ、ケーブルが接続されていて、端末の電源が入っていれば、各端末に対して `getty` プロセスが起動し、それぞれの端末にログインプロンプトが表示されるはずです。

<a id="term-debug"></a>
### 接続のトラブルシューティング

どれほど細心に手順を進めても、端末のセットアップ中に問題が生じることはあります。よくある症状と対処法の例を次に示します。

ログインプロンプトが表示されない場合は、端末の電源コードが差し込まれ電源が入っていることを確認してください。パーソナルコンピュータを端末として使っている場合は、正しいシリアルポートに対して端末エミュレーションソフトウェアが起動していることを確認してください。

ケーブルが端末側と FreeBSD コンピュータ側の双方にしっかり差し込まれていること、および適切な種類のケーブルであることを確認してください。

端末側と FreeBSD 側で bps 速度とパリティの設定が一致していることを確認してください。ビデオディスプレイ端末の場合は、コントラストや輝度の調整が十分上がっていることを確認してください。印字端末（プリンティングターミナル）の場合は、用紙とインクが十分にあることを確認してください。

`ps` を使って、`getty` プロセスが起動してその端末を担当しているか確認します。たとえば次の出力では、2 番目のシリアルポートである `ttyu1` 上で `getty` が動作し、`/etc/gettytab` の `std.38400` エントリを使用していることがわかります。

```shell
# ps -axww|grep ttyu
22189  d1  Is+    0:00.03 /usr/libexec/getty std.38400 ttyu1
```

`getty` プロセスが動作していない場合は、`/etc/ttys` でそのポートが有効になっているか確認してください。`/etc/ttys` を変更したあとは、忘れずに `kill -HUP 1` を実行してください。

`getty` プロセスは動作しているのにログインプロンプトが表示されない場合、またはプロンプトは表示されるもののキー入力を受け付けない場合は、端末またはケーブルがハードウェアハンドシェイクに対応していない可能性があります。`/etc/ttys` のエントリを `std.38400` から `3wire.38400` へ変更し、変更後に `kill -HUP 1` を実行してみてください。`3wire` エントリは `std` と似ていますが、ハードウェアハンドシェイクを無視します。`3wire` を使用する場合は、バッファオーバーフローを防ぐために bps 速度を下げるか、ソフトウェアフロー制御を有効にする必要が生じることもあります。

ログインプロンプトの代わりに文字化けが表示される場合は、端末と FreeBSD の間で bps 速度とパリティ設定が一致しているか確認してください。`getty` プロセスを確認し、正しい *getty* タイプが使われているか確かめてください。異なっている場合は、`/etc/ttys` を編集して `kill -HUP 1` を実行します。

文字が二重に表示され、入力したパスワードまで画面に表示されてしまう場合は、端末または端末エミュレーションソフトウェアの設定を「半二重（half duplex）」または「ローカルエコー（local echo）」から「全二重（full duplex）」へ切り替えてください。
