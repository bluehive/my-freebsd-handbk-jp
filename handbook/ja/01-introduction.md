## FreeBSD へようこそ

FreeBSD は、オープンソースで標準に準拠した Unix 系オペレーティングシステムです。対応アーキテクチャには x86（32/64 ビット）、ARM、AArch64、RISC-V、POWER、PowerPC などがあります。

プリエンプティブなマルチタスク、メモリ保護、仮想記憶、マルチユーザ機能、SMP 対応、各種言語・フレームワーク向けのオープンソース開発ツール、X Window System / KDE / GNOME を中心としたデスクトップ機能など、今日当たり前とされている機能をひととおり備えています。

特に強い点は次のとおりです。

- **寛容なオープンソースライセンス**  
  ソースの改変・拡張が自由で、オープンソース製品にもクローズド製品にも組み込めます。コピーレフト特有の制限を課さず、ライセンス非互換の問題も避けやすいです。
- **強い TCP/IP ネットワーキング**  
  業界標準プロトコルを実装し、性能とスケーラビリティを継続的に高めています。サーバやルータ／ファイアウォール用途に向き、実際に多くの企業・ベンダーがそれを理由に採用しています。
- **OpenZFS の完全統合**  
  root-on-ZFS、ZFS Boot Environments、障害管理、管理の委譲、jail 連携、FreeBSD 向け文書、インストーラ対応などを含みます。
- **充実したセキュリティ機能**  
  Mandatory Access Control（MAC）から Capsicum による capability／サンドボックスまで。
- **対応アーキテクチャ向けの事前構築パッケージが 3 万超**  
  加えて Ports Collection でカスタムビルドもしやすいです。
- **ドキュメント**  
  Handbook や他著者の書籍に加え、man ページがあります。ユーザランドのデーモン・ユーティリティ・設定ファイルだけでなく、カーネルドライバ API（section 9）や個別ドライバ（section 4）も対象です。
- **単純で一貫したリポジトリ構成とビルドシステム**  
  カーネルとユーザランドを単一リポジトリで扱い、統一されたビルドと開発プロセスにより、派生製品への組み込みがしやすいです。
- **Unix の思想への忠実さ**  
  振る舞いをハードコードした巨大な「全部入り」デーモンより、組み合わせ可能な設計を好みます。
- **Linux とのバイナリ互換**  
  仮想化なしで多くの Linux バイナリを実行できる場合があります。

FreeBSD は、カリフォルニア大学バークレー校 Computer Systems Research Group（CSRG）による 4.4BSD-Lite を基盤とし、BSD 系開発の伝統を継いでいます。CSRG の成果に加え、FreeBSD プロジェクトは実負荷下での性能と信頼性を高めるために膨大な人時を投じてきました。他のオープンソースや商用製品に匹敵する性能・信頼性に、他では得にくい先端機能を組み合わせています。

### FreeBSD で何ができるか

用途は想像力の範囲にほぼ限られます。ソフトウェア開発から工場自動化、在庫管理、遠隔衛星アンテナの方位補正まで——商用 UNIX® でできることなら、FreeBSD でもできる可能性が高いです。世界中の研究機関や大学が開発した高品質なアプリケーションも、多くの場合ほとんど無償に近い条件で利用できます。

ソース自体が自由に入手できるため、特別な用途向けに極端なまでのカスタマイズが可能で、主要商用 OS では難しいやり方も取れます。実際の利用例の一部を挙げます。

- **インターネットサービス**  
  組み込みの堅牢な TCP/IP により、次のような用途に向きます。  
  - Web サーバ  
  - IPv4 / IPv6 ルーティング  
  - ファイアウォールおよび NAT（いわゆる IP マスカレード）ゲートウェイ  
  - FTP サーバ  
  - メールサーバ  
  - ストレージサーバ  
  - 仮想化サーバ  
  - その他
- **教育**  
  計算機科学や関連工学の学生にとって、OS・アーキテクチャ・ネットワークを「中を見て手を動かす」形で学ぶ良い材料です。CAD・数学・グラフィック系の自由ソフトも多く、コンピュータを「別の仕事の道具」として使う人にも有用です。
- **研究**  
  システム全体のソースが得られるため、OS 研究や他分野の CS 研究の基盤になります。自由に使える性質のおかげで、特別なライセンス契約を気にせず遠隔のグループが議論・共同開発しやすいです。
- **ネットワーク機器**  
  新しいルータ、DNS、内部網を守るファイアウォールが必要なら、隅の使っていない PC を高度なパケットフィルタ付きルータに変えることもできます。
- **組み込み**  
  ARM / AArch64 / PowerPC 対応と堅牢なネットワーク、寛容な BSD ライセンスにより、組み込みルータやファイアウォール等の土台として使われます。
- **デスクトップ**  
  無償の X11 や Wayland を用いた安価なデスクトップとしても使えます。GNOME や KDE など多数のデスクトップ環境から選べます。中央サーバからディスクレス起動し、端末側のコストと管理負荷を下げる構成も可能です。
- **ソフトウェア開発**  
  基本システムに C/C++ コンパイラとデバッガ一式が付きます。他言語のサポートは ports / packages 経由で拡充できます。

FreeBSD はダウンロードおよび多くのクラウド上で無償で利用できます。入手方法は Handbook の「Obtaining FreeBSD」（本リポジトリでは今後 `appendix-a-obtaining-freebsd.md` 予定）を参照してください。

### 誰が FreeBSD を使っているか

FreeBSD は Web 配信能力で知られてきました。製品やサービスを FreeBSD 上に置く企業の声は [FreeBSD Foundation の testimonials](https://freebsdfoundation.org/about-us/testimonials/) に、製品一覧は [Wikipedia の List of products based on FreeBSD](https://en.wikipedia.org/wiki/List_of_products_based_on_FreeBSD) にもまとめられています。

## FreeBSD プロジェクトについて

以下では、簡単な歴史、プロジェクトの目標、開発モデルの背景を示します。

### FreeBSD の簡単な歴史

FreeBSD プロジェクトの始まりは 1993 年初頭で、非公式 386BSD Patchkit の最後の 3 人のコーディネータ——Nate Williams、Rod Grimes、Jordan Hubbard——の発想が一部にあります。

当初の目標は、patchkit では解決しきれない問題を直すための、386BSD の中間スナップショットを作ることでした。仮称は 386BSD 0.5 または 386BSD Interim でした。

386BSD は Bill Jolitz の OS で、当時ほぼ 1 年近く手入れが滞っていました。patchkit が膨らむ一方だったため、中間の「掃除」スナップショットで Bill を助けようとしました。しかし Bill が突然プロジェクトへの承認を取り下げ、代わりに何をするかも明確でなく、計画は頓挫しました。

3 人は Bill の支援がなくても目標は価値があると考え、David Greenman が付けた名称 **FreeBSD** を採用しました。当時の利用者と相談して初期目標を定め、実現の兆しが見えると Jordan は Walnut Creek CDROM に連絡し、インターネットに簡単にアクセスできない人向けの配布改善を探りました。Walnut Creek CDROM は CD 配布の考えを支持しただけでなく、作業用マシンと高速回線まで提供しました。当時まったく無名のプロジェクトへの異例の信頼がなければ、FreeBSD がここまで早く進むことはなかったでしょう。

最初の CD-ROM（および広くネット向け）配布は **FreeBSD 1.0**（1993 年 12 月）でした。U.C. Berkeley の 4.3BSD-Lite（"Net/2"）を基に、386BSD と Free Software Foundation の部品も多く含みます。初回としてはまず成功し、1994 年 5 月の **FreeBSD 1.1** が続きました。

その頃、Novell と U.C. Berkeley の Net/2 を巡る長年の訴訟が決着し、予期せぬ暗雲が立ちました。和解条件として、Net/2 のうち 3 ファイルが「権利付き（encumbered）」と認められ、Novell（AT&T から取得）の所有として除去が必要になりました。引き換えに Berkeley は、将来の 4.4BSD-Lite が encumbered でないと宣言され、既存 Net/2 ユーザは移行を強く推奨される、という Novell の了解を得ました。FreeBSD も対象で、1994 年 7 月末までに Net/2 ベース製品の出荷を止める期限が付きました。期限前の最後のリリースとして **FreeBSD 1.1.5.1** が認められました。

その後プロジェクトは、かなり未完成だった 4.4BSD-Lite の部品から事実上つくり直す困難な作業に入りました。除去されたのは System V 共有メモリとセマフォ関連の 3 ファイルだけでしたが、BSD 配布側にも多くの変更があり、FreeBSD 側の成果を 4.4BSD-Lite に合流させるのは大仕事でした。移行完了は 1994 年 11 月、世界向け **FreeBSD 2.0** は 12 月でした。まだ粗さは残っていましたが大きな成功で、1995 年 6 月のより堅牢で導入しやすい **2.0.5** が続きました。

以降、FreeBSD は安定性・速度・機能を高めながら一連のリリースを重ねています。

長期の開発は CURRENT（main）ブランチで続き、作業の進捗に応じてスナップショットが [snapshot サーバ](https://download.freebsd.org/snapshots/) から公開されます。

### FreeBSD プロジェクトの目標

目標は、**どんな目的にも使える、余計なひも付きのないソフトウェアを提供すること**です。コードやプロジェクトに大きく投資してきた人も多く、時おり金銭的見返りがあれば嬉しいとは思いますが、それを要求するつもりはありません。最優先の「使命」は、目的を問わず誰にでもコードを届け、可能な限り広く使われ、広く利益を生むことだと考えています。これがフリーソフトウェアの根本的な目標の一つであり、私たちはそれを支持します。

ソースツリー内の GNU GPL / LGPL 下のコードには、やや強い条件が付きます（通常とは逆に、アクセス強制の側です）。GPL ソフトウェアの商用利用で生じうる複雑さもあるため、合理的な選択肢がある場合は、より緩やかな **BSD ライセンス**での寄稿を好みます。

### FreeBSD の開発モデル

FreeBSD の開発は非常にオープンで柔軟で、世界中の数千人の寄稿の上に成り立っています（[contributors 一覧](https://docs.freebsd.org/en/articles/contributors/) 参照）。インフラにより、インターネット越しの協働が可能です。新しいボランティアを常に歓迎しており、関わりを深めたい方は [Contributing to FreeBSD](https://docs.freebsd.org/en/articles/contributing/) を参照してください。

知っておくとよい点:

**Git リポジトリ**  
長年中心ツリーは CVS で管理され、2008 年 6 月に SVN へ移行しました。ツリー拡大と履歴量により CVS の技術的限界が明らかになったためです。Documentation と Ports も 2012 年に SVN へ。2020 年 12 月に Source と Documentation が Git へ、Ports は 2021 年 4 月に続きました。ソース入手は Handbook の Obtaining the Source、Ports は Using the Ports Collection を参照。

**コミッター**  
Git リポジトリへ push でき、ソースを変更する権限を持つ人々です（「committer」は変更を取り込む `commit` に由来）。誰でも [Bug Database](https://bugs.FreeBSD.org/submit/) に報告できます。報告前にメーリングリスト、IRC、フォーラムで「本当にバグか」を確認するとよいです。

**Core チーム**  
会社にたとえれば取締役会に近い役割です。プロジェクト全体の健全さと方向性を見ます。責任ある開発者をコミッターに招くこと、メンバーの交代も役割です。現行 core は 2024 年 5–6 月にコミッター候補から選出。選挙は 2 年ごとです。

> **注**: core の多くもボランティアであり、金銭的利益を前提にしません。「commitment」を「保証されたサポート」と誤解しないでください。「取締役会」のたとえは厳密ではなく、より良く判断すれば FreeBSD のために人生を捧げた人々、と言う方が近い場合もあります。

**FreeBSD Foundation**  
米国 501(c)(3) の非営利で、世界の FreeBSD プロジェクトとコミュニティを支援・推進します。助成による開発、緊急対応と新機能実装のスタッフ、インフラ用ハードウェア、テスト／CI／自動化の強化、会議での広報、ワークショップや教材、契約・ライセンスなど法的主体としての代表を行います。  
サイト: https://freebsdfoundation.org/

**外部の寄稿者**  
最大の開発者層は、フィードバックとバグ修正を絶えず送る利用者自身です。ベースシステムの開発に触れる主経路は関連メーリングリスト（hackers、ports、doc など）です。詳細は Resources on the Internet を参照。  
コード提供だけが貢献ではありません。[Contributing](https://docs.freebsd.org/en/articles/contributing/) を参照してください。

要約すると、開発モデルはゆるい同心円です。中央集権に見える部分は、**利用者が一つのコードベースを追いやすくする**ためであり、寄稿者を締め出すためではありません。安定した OS と、一貫した ports 上の多数のアプリを簡単に入れられることが目的で、その点でよく機能しています。

開発者として加わる方には、現メンバーがプロジェクトの継続的成功に払っているのと同様の dedications を少しでも、とお願いするだけです。

### サードパーティプログラム

基本配布に加え、よく求められるプログラムの移植集（Ports）があります。HTTP サーバからゲーム、言語、エディタまで幅広いです。ポート数は数千規模で、Ports Collection 全体のディスク要件はリリース時点の文書を参照してください。インストールしたいプログラムのディレクトリに移り `make install` するだけで、必要な元配布は動的に取得されます。

ほとんどのポートは事前構築 **package** としても提供され、ソースからビルドしたくない場合は `pkg install` で入れられます。詳細は「アプリケーションのインストール: Packages と Ports」の章を参照。

### 追加ドキュメント

サポートされる FreeBSD では、初期セットアップ時にインストーラで追加ドキュメントを `/usr/local/share/doc/freebsd` 以下へ入れる選択肢があります。後から package でも入れられます。

```shell
# pkg install en-freebsd-doc
```

地域版では `en` を言語接頭辞に置き換えます。一部の翻訳は古く、現在は正しくない情報が含まれる場合があります。

ローカルの Handbook PDF の例:

- Handbook: `/usr/local/share/doc/freebsd/en/books/handbook/handbook_en.pdf`
- FAQ: `/usr/local/share/doc/freebsd/en/books/faq/faq_en.pdf`

最新の文書は [Documentation Portal](https://docs.FreeBSD.org/) を参照してください。

商標はそれぞれの所有者に帰属します。
